The development LTV maximum is 8,000 bps. Liquidation threshold must be higher and at most 9,000 bps. The current close factor is at most half the stored debt rounded up to a raw unit, and collateral bonus is 5%. Founder approval is still required for release values. Per-market caps are set by the market creator. Counting independent markets for a single pair is necessary when defining a global portfolio limit. The per-block rate model assumes 2,102,400 blocks per year. Between mainnet blocks 76,761,644 and 76,848,044, 86,400 blocks elapsed in 86,400 seconds. Extending that observed cadence to a 365-day year gives 31,536,000 blocks, **15 times** the model assumption. At constant utilization this would multiply simple annual accrual by 15 before compounding. Recalibrate or review a time-based release model and its displayed APR. ## Governance, counterparties and recovery

Under the proposed role split, a founder-selected threshold multisig proposes changes to a timelock. A separate narrowly scoped guardian can stop new risk immediately. Resumption, looser caps, new listings, policy or oracle replacement go through delay. The handoff suggests at least 24 hours for risk-increasing changes, subject to founder approval. Existing positions need a documented treatment when parameters change. Use immutable or delayed pair/feed/adapter mappings, a bounded policy-vetting process, per-position caps and aggregate caps across permissionless factories. No role should sweep user funds. Test admin removal, grant rotation, loss of a signer and policy-independent exits. Source-check the production oracle for manual price routes and any remaining test setters. [Development security model](../SECURITY_MODEL.md) · [OpenZeppelin access-control and timelock guidance](https://docs.openzeppelin.com/contracts/5.x/access-control)

At public block **76,848,044**, factory `0x1f09DAeFA827f02CBb40967cc91b259763760761` reported `isSealed() == false`, owner `0xB3D85b42A045c1A88D800CAD0F55d2566a4D3138`, and ERC-1967 implementation `0x336e9F0F4c3fEe7C8c803377e4DEA00293f4ae2a`. CPU 410 resolves to circuit beacon `0xf70d1ed4f62CF3780157B0b421b7E2F45bD0991C`. Its owner is zero and its implementation is `0x977f217887E085D298Cb3819cDAD5A0ee35F29B2`. Factory upgrades affect future deployments and factory assertions. The observed renounced beacon limits the usual owner-upgrade route for that existing CPU. Review their separate authorities, bytecode and dependencies. The registry pins a processor's external code hash. A proxy code hash alone cannot establish the logic behind it. Record and monitor each address, implementation slot, code hash, factory membership and circuit bytes. Keep repay and safe exits available if any watch changes. [Fresh read and bytecode hashes](../../evidence/session3-release/processor.json) · [Historical upgrade and beacon ownership](../TAPEOUT_INTEGRATION.md)

The local child-fork liquidation consumed **290,896 gas**, and the dual-circuit fork borrow consumed **771,264 gas**. The liquidation used mock assets, an already funded local actor and no DEX sale. A release needs a real debt-token budget plus OKB for gas and any oracle update, realistic calldata and L1 costs, an independent liquidator on call, redemption liquidity and an actual disposal route. For each approved cap, measure realizable post-fee proceeds at the close-factor size, subtract debt outlay, updater, swap and transaction costs, and include slippage and a buffer for price movement. Rehearse successive liquidations during a correlated price move. Propose a cap only where the quoted route **and committed prefunded inventory** cover the aggregated stressed sales. The founder must approve that cap and capital. **Liquidator economics.** The imported pToken allocates 2.8% of seized shares to protocol reserves. At equal oracle and executable prices, the gross liquidator has approximately `1.05 × (1 − 0.028) = 1.0206` units of value for each debt unit paid, before rounding, gas, exchange costs and price movement. A two-percent discount to the oracle sale price leaves only `1.0206 × 0.98 − 1 = 0.000188` units (1.88 bps) before those costs. Quoting a 5% liquidator profit would materially overstate the margin available to pay for liquidation. Check available borrower shares, liquidation close factor, token cash/redemption and actual pool proceeds at the intended size. A 20,000-USDC outstanding loan could require up to 10,000 USDC of prefunded inventory for one close-factor-sized repayment. At this pool snapshot, recovering that outlay by selling seized underlying required at least 128.645774847682961230 WOKB before execution gas, adverse price moves and any funding cost. This example sets neither an approved loan cap nor a claim that such a loan exists. A release rehearsal should combine the exact liquidation receipt, borrower share availability, the protocol seizure split, redemption and final swap in one fork state. Repeat across blocks under lower depth and stale quotes, then obtain a liquidator funding commitment for multiple simultaneous tickets.

These observations support a mainnet-fork experiment and a clearly labeled mock testnet demo. They leave the real testnet route and production stressed liquidation capacity unqualified. ## What Claude can accept

The development evidence and independent research are suitable for the submission's technical appendix. For a funded pilot, treat missing production risk controls and the missing verified release build as release-blocking. Treat unsupported oracle freshness, uncalibrated rates, uncommitted liquidation capital and unresolved external implementation trust as high operational or dependency risks for the proposed pair. These are desk-review classifications. Independent source review can identify additional findings. Before circulating a candidate for approval, name the owner and closure evidence for each row above. Keep the mainnet financial manifest read-only while any row remains open.
