Index 501 is OKX's identifier for Solana. The proposed input is a list of `{chainIndex, address, role}` records. A user can opt to watch the same EVM address on three chains. A smart contract's controller and deployment are chain-specific even when address bytes match. Display the owner wallet, each Sentinel account and a manually supplied watch address separately. For Solana use the supplied wallet owner address and preserve the case of every mint address. A supplied address establishes a watchlist entry only. ## Read sequence

1. Discover balance support with `GET /api/v6/dex/balance/supported/chain` on `https://web3.okx.com`. Intersect the returned string identifiers with the four requested networks. Record absence as unsupported. Refresh the capability cache daily and after a provider unsupported-chain response. [Balance capability endpoint](https://web3.okx.com/onchainos/dev-docs/wallet/balance-api-chains)
2. Fetch wallet inventory with `GET /api/v6/dex/balance/all-token-balances-by-address?address=…&chains=…`. Identical selected EVM addresses can share one comma-separated chains query. Query Solana independently. Validate every returned chain/address pair. Key assets by chain and contract or mint, with a distinct native-asset identity after verifying the provider's encoding. Keep token amounts and prices as decimal strings. Use bigint for raw quantities when supplied. A missing raw quantity or USD price stays unknown. Leave the provider's default risk filtering on. OKX documents honeypot coverage on Ethereum, Base and Solana among these networks. Keep coverage on X Layer unspecified. [Wallet balances and risk fields](https://web3.okx.com/onchainos/dev-docs/wallet/balance-api-all-token-balances)
3. Fetch the USD estimate for each chain/address separately with `GET /api/v6/dex/balance/total-value-by-address`. Use `assetType=1` for a wallet-token subtotal. The other documented selectors are `0` for the combined token/DeFi estimate and `2` for DeFi. Present the selected scope with the value. Adding a combined total to its breakdown or valuing a vault share again as underlying would double-count assets. Exclude testnet mocks from every USD total. [Valuation API](https://web3.okx.com/onchainos/dev-docs/wallet/balance-api-total-value)
4. For a separate provider-indexed protocol tab, use the read-only `POST /api/v6/defi/user/asset/platform/list` with `walletAddressList`, followed by `POST /api/v6/defi/user/asset/platform/detail` with the returned protocol identifier and chain. One address per chain per request preserves attribution. Keep each position's protocol, supplied/borrowed components, asset identities, share quantity and position ID when available. List support for a chain does not establish coverage of every protocol. For Sentinel collateral, debt, redeemable vault shares, liquidation checks and policy inputs, the verified adapter/book read at a known block remains authoritative. [Holdings overview](https://web3.okx.com/onchainos/dev-docs/wallet/defi-user-asset-platform-list) · [Protocol holdings detail](https://web3.okx.com/onchainos/dev-docs/wallet/defi-user-asset-platform-detail)

These four reads expose no documented page or cursor parameter. The two balance endpoints accept at most 50 chains per address. The detail request scopes results by returned protocol ID. Bound request fan-out per refresh and load individual protocols on demand. Flag a partial result if an expected detail response fails, coverage is uncertain or response limits are exceeded. A successful empty list can be displayed as “No holdings returned by OKX” for the queried scope. An error leaves the holdings count unknown.

## Refresh, access and acceptance

Each per-chain result should carry `subject`, `source`, `endpoint`, `requestedAt`, `receivedAt`, `providerUpdatedAt`, `blockOrSlot`, `status` and `reason`. Preserve absent source timestamps and block/slot as null. For DeFi overview preserve `updateAt` in milliseconds and map `assetStatus=2` to updating. The balance responses document neither a block number nor snapshot time. Suggested display policy is a one-minute cache, an explicit timestamp for cached values and a stale label after five minutes. Both intervals are client choices. A four-chain total may combine observations from different times. Show subtotals and coverage for partial observations. [OKX holdings update metadata](https://web3.okx.com/onchainos/dev-docs/wallet/defi-user-asset-platform-list)

Only a server-side read service would receive `OKX_API_KEY`, `OKX_API_SECRET` and `OKX_API_PASSPHRASE`. Sign the exact method, encoded path/query and raw body with the UTC timestamp using OKX's HMAC-SHA256 and Base64 scheme. Allow only the named read routes. Keep the service independent of transaction signers. A missing credential, denied entitlement or exhausted quota makes the affected read unavailable. Honor retry-after and use bounded backoff for transient reads. Label cached observations with their original times. Never expose credentials to a browser, MCP response or diagnostic. The operator can request project quota and permission for both Balance and DeFi Holdings through the existing founder channel. [Official authentication](https://web3.okx.com/onchainos/dev-docs/home/api-access-and-usage)

Before enabling the UI, capture one sanitized authenticated observation per network for an explicitly chosen public watch address. Compare one identifiable balance on each network with an independent EVM RPC or Solana RPC at a recorded block or slot. Confirm native asset and decimal normalization, a missing price, an updating/partial response, and a failed lookup that preserves its timestamped last success. Verify a known protocol position through its own book before advertising protocol coverage. The current testnet demo and mainnet-fork receipts provide no evidence for this external provider integration.
