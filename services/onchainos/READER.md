# Server-side OKX views

Import `handlePortfolio(searchParams, opts)` and `handleQuote(searchParams, opts)` from `services/onchainos/reader.mjs` in the Node route handlers. Each is async and returns `{status, body}` for the route’s JSON response. Pass `request.nextUrl.searchParams` or another `URLSearchParams`. Pass `{env, fetch, now: Date.now}` as server-only dependencies, with stable fetch and clock functions shared between the routes. The reader consults only the injected environment. Serve the response with `Cache-Control: private, no-store` so wallet lookups stay out of shared HTTP caches.

| Route | Query | Result |
| --- | --- | --- |
| `GET /api/onchainos/portfolio` | `subjects=196:<address>,1:<address>,8453:<address>,501:<address>` | One to four distinct chain/address pairs. EVM addresses return checksummed. Solana owners and mints retain exact base58 case. Network rows are in canonical subject order. |
| `GET /api/onchainos/quote` | `from=WOKB&amount=1000000000000000000` | Fixed pair on 196, either direction. Supply `from=WOKB` or `from=USDC` and a positive raw uint256 decimal string. The quote carries the actual token addresses. |

Invalid, repeated or extra query parameters return HTTP 400 with `{"error":"Invalid request"}` before provider access. Valid queries return HTTP 200 and a status in the body. Display `empty` only after confirmed parsing of an empty inventory and its subtotal. `unavailable`, `unsupported`, `not-entitled` and `rate-limited` represent unknown balances. Reasons are null on success (including empty), or one of `credentials-missing`, `unsupported-chain`, `not-entitled`, `rate-limited`, `provider-unavailable`, `malformed-provider`, `native-marker-unverified`. Each subject resolves independently. A native row has `tokenAddress:null` and `isNative:true`. A token with hostile display text retains its validated token address and balance, with symbol `UNKNOWN`. All amounts and USD prices are decimal strings; missing raw units or prices are null. `walletUsd` is the wallet-token subtotal (`assetType=1`). Timestamps describe the service observation, including when returning a cached result. They do not identify a provider block.

The OKX balance response convention uses an empty contract string for the native asset. This reader requires the matching chain symbol as well: OKB on 196, ETH on 1 and 8453, and SOL on 501. Wrapped assets retain their contract or mint identities. Conventional zero/DEX/system addresses and conflicting native markers fail closed. Each network still needs Claude’s positive comparison to an independent RPC before Fable enables it. [OKX balance inventory and Ethereum example](https://web3.okx.com/onchainos/dev-docs/wallet/balance-api-all-token-balances) · [OKX Balance API native contract marker](https://web3.okx.com/onchainos/dev-docs/wallet/balance-api-token-balances)

The worker coalesces in-flight reads, caches completed portfolio observations for 60 seconds and quotes for 15 seconds, and keeps a successful supported-chain check for 24 hours and an unsuccessful one for 60 seconds, so at most one discovery dispatch per minute after a failure. Each supported subject has two read endpoints, inventory followed by wallet-token valuation. Each subject has a two-dispatch budget including retries. A four-subject cache miss with discovery costs at most nine physical calls, even during provider failures. Transient HTTP 429/5xx responses can use one retry with bounded backoff only while budget remains. If an inventory retry takes the second slot, that subject reports rate-limited and its subtotal stays unknown. A quote can use two attempts. Every physical attempt consumes the shared rolling limit of 30 provider requests per minute. At most two are in flight per instance. Each serverless instance has its own budget. Known provider error categories are mapped to fixed application codes. Raw responses, headers and provider diagnostic text are never returned.
